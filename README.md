## beta0.9.3 带来了什么

**beta0.9.3 已于 2026-09-27 发布，上方下载就是这一版。** 课程笔记、飞书文档入口、庭院环境与日常入口随本版一起交付，各页排版、暮色阅读和分区导航也已统一；界面验收记录在 [STATUS 第 65 节](docs/STATUS.md#s65)，发布前的全仓代码审查修复见[第 66 节](docs/STATUS.md#s66)。学校真实业务和飞书多人协作的验收边界不变。

### 每一页，都住在同一个庭院里

各页的窗景缩成小门厅，移除重复标题；庭院先显示伙伴、农田或小游戏，再给下一步建议。摸头、喂食等操作提前到伙伴房间上方。暮色保留暖纸面，统一建设、宠物动作册、2048 与委托的文字颜色，修复浅字贴浅底的问题。

设置分为**风景与偏好 / 桌面陪伴 / 存档与隐私 / 关于与更新**；窄窗使用整齐的两列分区按钮。未保存的个人展示在切页后保留，成功保存后才更新本机记录。课表、公告、农田与设置子页可通过地址恢复，刷新和前进后退不用重新找入口。书屋显示搜索结果数量与清除入口，筛选不匹配时保留当前正文；长书架与笔记列表分别滚动。

学校登录和成绩读取跟随同一个培养层次选择；课表读取有等待和重试状态，校历失败不再停在“正在读取”，空公告也有明确说明。以上改善操作与反馈，不代表学校账号或预约已完成真实验收。

上一轮（PR #21）已实际检查常规桌面和 420px 首页／笔记、暖阳／暮色及像素庭院／雨后书屋；未见横向溢出。大纲定位、笔记归属调整、首页继续最近页与设置直接导出备份也已使用合成资料走通，构建交付状态见 STATUS 第 64.2 节。

校园网页先显示连接状态、刷新与诊断；外网可用时按需展开「连接 / 更换账号」。学习空间合为一个「打开学校预约」主入口，并提供「先看空位」；图书馆入口放在规则之前，详细规则按需展开。公告分区首次进入时自动读取记住的学院，失败保留原因，可手动刷新，不后台轮询。

### 从庭院走进书屋，把学到的留下来

首页点**去书屋写笔记**，或进入**学习书屋 → 课程笔记**。课程可以手动建立，不需要学校登录；支持空白、课堂记录和阅读／组会模板，标题与正文搜索、Markdown 书写和阅读、专心书写、回收站恢复。内容自动保存到本机，保存状态可见；多窗口冲突会保留当前草稿，提示先导出再读取最新版本。正常退出安装版前会先保存笔记；失败时默认返回处理，只有明确选择放弃未保存修改才继续退出。保存过程中再次点击操作会提示等待原因。

笔记里的下一步也能接回日常：选中一句话可加入学习待办，或从正文工具栏开始 **25 分钟专注**。新增可折叠的**本页大纲**，在书写或阅读时跳到对应标题，也能直接调整这页归属的课程。首页「继续写笔记」会定位最近修改且未删除的一页，清除旧搜索或回收站筛选。写字数量、导入内容不会直接变成庭院奖励。

支持导入 Markdown／TXT、单篇导出 `.md`、整本导出和恢复 JSON（含课程、笔记、当前草稿与回收站）。设置 → 存档与隐私中的「备份课程笔记」现在直接导出整本备份，课程书架的备份入口也保留。笔记单独保存在 `.szunet/notebook-v1.json`，**是本机明文文件**，与庭院 `workspace-v1.json` 分开；换电脑需分别备份。当前是文本笔记，尚未接入 AI 整理、PDF／课件解析、图片附件或云端同步。

### 课程共学交给飞书，个人笔记留在本机

每门课可以绑定一份自己有权限的飞书 Docx／Wiki 文档。点击**打开共享文档**，安装版在独立窗口打开飞书原页面，便携／浏览器模式使用浏览器；共同编辑、评论与权限由飞书处理。

需要读入本机时，应用调用**用户自己安装并配置的 `lark-cli`**，以该用户授权身份读取所选文档，再新建一页带来源链接的本机副本。连接按钮提供官方只读授权入口；没有配置 CLI 时仍可打开共享原文。**这不是双向同步**：本机修改不回写飞书，也不使用开发者共享账号代替用户。

飞书官方窗口登录和 CLI 读取授权相互独立；窗口会话仅在本次应用运行中保留，CLI 凭据由用户自己的 CLI 管理。本机已实际识别安装的 CLI，并正确提示用户身份尚未授权；没有发起授权或读取私人文档。本版没有创建组织、邀请同学或改变文档权限，项目专属组织加入入口尚待配置；真实飞书登录、受权限约束的文档导入和多人协作仍待验收，不能仅凭接入代码宣称已打通。

当前可见页面共用一块场景画布：首页展开完整风景，其他房间使用紧凑窗景，笔记页进一步缩小门厅，把位置留给正文。同一环境与动画偏好下，切页重新挂载现有画布；换环境或改变动态设置时释放旧资源。视野之外和后台暂停，关闭动画或启用系统减少动态时显示静帧；不支持立体渲染时保留像素校园和全部操作。

摸摸伙伴或保存待办时，背景继续使用同一块画布，保持动画连贯。伙伴平时只显示小名牌，回应后再自动收起气泡；暮色文字、远景树带和书屋铺地也完成了收尾调整。

底部提示条现在跟随当前伙伴：切换宠物、修改名字、切换页面和重新打开后，头像与名字保持一致。此修复已包含在 beta0.9.3 安装包中；验收记录见 STATUS 第 60.4 节。

### 把收成摆上伙伴小桌

2048 的棋子现在来自同一座庭院：**2 种子袋 → 4 嫩芽 → 8 小萝卜 → 16 草莓 → 32 蓝莓 → 64 荔枝 → 128 萝卜篮 → 256 草莓篮 → 512 蓝莓篮 → 1024 荔枝篮 → 2048 荔宝丰收礼**。继续合到 4096 或以上会换上庆典装饰，完整数字始终保留。

农田与棋盘共用作物图案，移动中的棋子和停下后的棋子使用同一份画稿。桌边会提示「这局合到了什么、下一阶是什么」，完整素材图鉴默认折叠。原有合并规则、分数、存档、悔棋和每日种植补给均保持不变；棋盘图案不会直接变成农田库存，仍由领取补给把这一局接回种植。

### 伙伴开始有自己的动作和脾气

六种伙伴（含旧存档的阿青）各有 **18 组动作、每组 6 帧，共 648 帧**独立像素画。原有日常动作之外，新增**浇水、抱回收成、递礼物、搭建、思考和拿手动作**；水壶、收成篮、小礼盒与小锤子有准备、动作和收势，眼睛、嘴、四肢、尾巴与叶片也分别变化。主窗口和桌宠使用同一个播放器，小屋「动作册」按日常、互动和庭院分组，可逐组播放、展开查看每一帧。另保留 30 张静态形象，用于减少动态效果和导出明信片。

**Pingu 重新画过了。** 黑脸小珠眼、短颈圆头、连到胸前的大白肚、鲜红突出嘴和橙色宽蹼足，共用一套画法覆盖静态与动画；高兴时嘴会真正张成喇叭。Skipper 继续保留独立的站姿、白脸和低眉，没有把两只企鹅画成换色版本。

设置保存成功后立即同步桌宠的动画开关，自定义时长开始专注也会立即同步；保存失败不会提前改变桌宠。睡眠和专注优先，拿手动作不会打断它们，减少动态时使用静态形象。本轮安装升级、重开和复用内核三条路径均通过：系统减少动态正常遵守，在隔离测试渲染器模拟允许动画后读取实际帧推进，最后恢复媒体条件与原偏好，没有改动 Windows 设置。

**1,656 句台词覆盖 23 类情境**，每只伙伴每类 12 句，按各自进度轮换并存档。新增播种、浇水、交付委托、建造、领取种子补给、开始专注和拿手动作的回应。栗栗继续一本正经地巡视纸箱，完全不知道自己丑萌；Pingu 会误会小东西，Skipper 连休息都当成后勤安排。台词按情境出现，不靠不停弹话增加存在感。

伙伴也来到农田旁边：播种、浇水、收获后可以直接看见它的动作与回应，不必回小屋才知道它说了什么。「看拿手动作」免费，不扣资源，也不增加成长或亲密度；本轮没有改变种植、委托或小游戏的经济规则。

### 从一颗种子，到湖边的一小块新布置

**专注与陪伴 → 备种和种植 → 收成 → 伙伴委托与庭院建设 → 真实场景和收藏。** 下列规则替代第 57 节初版小游戏奖励，庭院继续使用同一份种子、收成、荔枝币与伙伴成长。

- **伙伴小桌 · 一起备种。** 保留完整 2048、方向键 / WASD / 滑动、自动续盘、悔一步和最高纪录。当天实际合出 128 或以上，可领取一次**需求种子 ×1、8 币、成长 +3、亲密度 +2、心情 +10**，并计一次每日陪伴。种子优先补未完成委托和下一项建设的缺口，计算时包含篮子、已有种子及正在生长的作物；奖励不会给出尚未解锁的种子。领完可直接去播种，旧棋盘的大数字不能重复领取新一天奖励。
- **我的农田 · 收成有去处。** 选种时能看到哪些伙伴、哪项建设需要它；材料不足的委托直接带你去对应作物和空田。收成也能作为小屋点心喂给伙伴。集市「出售多余」会保留当天未完成委托与下一项建设所需的收成，再卖剩余数量。
- **庭院集市 · 送到真正提出委托的伙伴手里。** 每天三份固定需求，支付材料售价加 **3 / 3 / 4 币**答谢；提出委托的伙伴获得 **成长 +5、亲密度 +3**，不会错给当前选中的另一位伙伴。完成 1 / 3 / 8 / 15 份收下纪念物，无逾期惩罚。
- **回忆与建设 · 收成变成看得见的庭院。** 按下面的条件消耗材料与荔枝币建造，首次建成自动摆放；之后收起、摆出不再扣费。布置出现在首页、小屋和农田的像素场景中。
- **小屋收藏与「下一步」。** 2048 的五枚里程碑贴纸、委托纪念物和来访故事纪念物一起留在小屋。首页与庭院根据真实进度提示眼前可以做的一件事，直达成熟田块、可交付委托、建设、种子铺或专注；正在生长的作物计入准备进度。

### 首次使用

1. 到「**荔枝庭院 → 伙伴小屋**」选择一位伙伴。安装版的桌面宠物会同步切换。
2. 到「**我的农田**」看看已经种好的萝卜，约 1 分钟后就能收获；也可以先写一件待办、试一次 5 分钟专注。不需要登录学校账号。
3. 需要校园服务时，再打开公告、校历或学校入口。

需要连接校园网时，进入「校园网」，填校园卡号和统一身份认证密码，再点「登录校园网」。勾选记住后，凭据只会在认证成功时保存；连不上就运行「网络诊断」，查看问题出在哪一步。校园网登录与学校业务登录分别办理。

### 新存档的第一段体验

新存档有 40 荔枝币、3 份点心、4 颗萝卜种子、2 颗草莓种子，以及一块已经种好的萝卜。先选伙伴、写下一件小事，再开 5 分钟专注；完成并领取后得到 5 币和 5 成长。萝卜约 1 分钟成熟，立即浇水可缩短到约 45 秒，收获 2 个萝卜和 1 成长。没有学校账号也可以完成这段体验。

来访小故事按七个不同的日子推进，隔天回来不会归零；完成记录保存在本机。旧存档缺少的任务日期和专注历史不凭空补写，已有累计值、伙伴成长和已领纪念章继续保留。

### 打开与退出

- 安装版重复启动会聚焦已有窗口；已有同版本便携版后台服务时复用该服务。若提示后台版本过旧，先退出旧版再打开
- 安装版关闭主窗口后保留宠物与托盘；从宠物菜单选择「打开主窗口」，也可点击托盘重开。通过宠物菜单「退出应用」、托盘「退出」或「设置 → 关于与更新 → 退出应用」完整退出；只清理本次启动的引擎，复用的已有后台服务保留。便携版仍在所有窗口关闭约 10 秒后退出
- 刷新页面不会结束服务
- 首次打开会给一张可跳过的短引导，说明数据存在哪、怎么退出、先做什么
- 安装版不会默认新建开机自启项；「设置 → 桌面陪伴 → 登录 Windows 时启动」只在主动开启后登记，卸载时一并清除。便携版的自启开关和命令行 `szunet autostart` 继续可用；状态读取失败会明确提示

### 我的数据存在哪

- 默认在用户目录 `.szunet` 下
- 校园网密码按平台存放：Windows 用 DPAPI 加密（只有这台机器的当前账户能解开）；macOS 用系统钥匙串；Linux 用 Secret Service（`secret-tool`）。**三端都没有明文兜底**：机器上没有对应的系统安全设施时，保存会明确报错并说明原因，而不是偷偷落一个明文文件
- 庭院存档是 `workspace-v1.json`，普通 JSON，可自行备份；导出的存档不含校园账号密码
- 课程笔记单独存于 `notebook-v1.json`，**明文、未加密**；设置中点「备份课程笔记」，或在课程书架「导入与备份」导出整本笔记。庭院备份不包含笔记
- 换电脑前请在设置中导出存档，再在新电脑导入

## 校园网连接原理

<details>
<summary>教学区与宿舍区为什么需要不同的认证方式</summary>

深大校园网分成两个**互不通用**的区域，认证方式完全是两套东西：

| 区域 | 系统 | 协议特点 |
| :--- | :--- | :------- |
| 教学区 / 办公区 / 图书馆 | 深澜（SRun） | 2025 年寒假上线，密码经 HMAC-MD5，用户信息经 XXTEA 加密与自定义 Base64，另需 SHA1 校验和 |
| 宿舍区 / 教工区 | Dr.COM（ePortal） | 一次 GET 请求即可完成 |

由此带来两个麻烦：

1. **2024 年以前的教程和脚本在教学区全部失效** —— 它们都是为老的 Dr.COM 写的。
2. **报错信息五花八门没人解释** —— `ldap auth error`、`Rad:userid error1`、`登陆失败[05]`、
   `Unknow ac-type`…… 用户只能瞎试。

szuDesktop 同时对付这两件事：**一个按钮完成认证，一个按钮说出卡在哪一步。**

判区不看「门户能不能连上」，而看**协议指纹**（就是那套协议特有的握手行为：教学区看
`get_challenge` 能否握手、宿舍区看 ePortal 登录接口是否存在）。原因是实测发现宿舍门户
在教学区机器上首页同样返回 200，只测连通性会在掉线时误判成宿舍区，然后拿 Dr.COM 协议
去打一个不存在的接口。

</details>

## 命令行 szunet

不想开窗口、或者想把认证写进脚本时用。源码在 `cmd/szunet`，
`go build -o dist/szunet.exe ./cmd/szunet` 即可编译。

| 子命令 | 作用 |
| :----- | :--- |
| `login` | 登录（用 `config set` 保存的账号；临时换号用环境变量，见下） |
| `logout` | 注销下线 |
| `status` | 查看当前状态 |
| `detect` | 探测当前网络区域与接入点编号 |
| `diag` | 断线诊断，输出区域判定与协议指纹 |
| `config` | 查看 / 保存账号密码（`config set` 交互输入，密码不回显） |
| `autostart` | 开机自启设置（仅 Windows） |
| `vpn` | 校外访问校园网的三条官方通道指引（WebVPN / EasyConnect / 零信任）；**只是指引，不含实验 VPN 协议代码** |
| `version` | 查看版本号 |

```text
szunet config set                   # 先保存账号：交互输入，密码不回显
szunet login                        # 之后直接登录，不用再带密码
szunet detect                       # 看当前识别出的是哪个区域、接入点编号是多少
szunet login --zone teaching        # 指定走教学区协议（auto / teaching / dorm）
szunet login --ac-id 12             # 手动指定接入点编号
szunet diag                         # 连不上时先跑它，再按结论排查
```

脚本里保存账号用 `--password-stdin` 从管道传入密码，不进命令行参数：
`<输出密码的命令> | szunet config set -u 你的卡号 --password-stdin`。
临时换号也可以用环境变量 `SZUNET_USERNAME`、`SZUNET_PASSWORD`。
`-p` 只为兼容旧脚本保留，密码会留在 shell 历史和进程列表里，使用时会提示风险，**不推荐**。

`--help` 看全部参数。**不要把真实账号密码写进共享脚本或日志。**

macOS 上保存凭据（`config set`）走系统钥匙串：写入前会先用一次性条目自检这条路可用，失败时明确报错，不会退回把密码写进命令行参数（那样同机其他进程能看到）。

**一个必须说明的缺陷（F26）**：CI 新加的 macOS 探针在真机上跑出过一次 `passwords don't match`——
真实的 `security -w` **可能**要求输入两遍（密码 + 确认），而 beta0.7.1 与 beta0.7.2 只喂了一行，
所以在那些机器上 macOS 命令行版**存不了凭据**（会明确报错，不泄漏、不落明文，但功能不可用）。
这个行为不稳定：同一镜像 macOS 26.6.2 的后续 4 次运行都只问一遍。现已改为喂「密码 + 确认」两行，
两种情况下都成立（真机验证过「只问一遍」那种），**修复自 beta0.7.3 起发布**；那条探针也不再允许
失败被忽略，并已成为发布的前置条件。跟踪记录见 STATUS.md 的 F21 / F25 / F26。

## 常见问题

<details>
<summary><b>接了自己的路由器后登录不上</b></summary>

校园网每个接入点有独立编号（`ac_id`），你插哪个网口就得报哪个号。旧版本固定用 `1`，
而路由器那条线路要求 `12`，编号不对会被服务端直接拒绝。

现在程序按下面的顺序找编号，从上往下、哪个先成用哪个：

| 优先级 | 来源 | 可信度 |
| :-- | :-- | :-- |
| 1 | 你自己指定的（`--ac-id 12`） | 最高 |
| 2 | 这台机器在**这个网口**上认证成功用过的 | 高 |
| 3 | 未认证时被网络拦下，从它给的跳转地址里读出来的 | 权威 |
| 4 | 挨个试常见编号 | 低（界面上标「猜的」） |

**编号跟墙上那个网口走，不跟路由器走**：同一台路由器插回原来的口 → 编号不变；
换个口 → 变了；换一台路由器插原口 → 还是原来的编号。

出现「认证失败：ac_id 用错了」时用 `szunet detect` 看当前识别出的接入点。原理解析见
[docs/blog/ac_id-接入点编号.md](docs/blog/ac_id-接入点编号.md)。
</details>

<details>
<summary><b>杀毒软件报警</b></summary>

桌面便携版与 Electron 安装包目前都没有数字签名，可能触发系统提示（
首次运行会有 SmartScreen 提示）。但**不要把安全软件的所有提示都笼统当成误报**：
代码是开源的，可以自己看、自己编译（`go build`）后比对行为。
</details>

<details>
<summary><b>关掉浏览器窗口，程序还在跑吗</b></summary>

安装版关主窗口后继续常驻；从宠物菜单选择「打开主窗口」，或点击托盘重新打开。从宠物菜单「退出应用」或托盘「退出」完整退出并清理自己启动的引擎，复用的已有服务保留。便携版关闭**所有**窗口约 10 秒后退出；
刷新页面不会结束服务。也可选择「设置 → 关于与更新 → 退出应用」。只启动便携版后台服务时，给 `szudesktop.exe` 加 `--no-open`
（面向无头 / sidecar 场景；Electron 外壳也是用它在后台拉起 Go 引擎的）。
</details>

<details>
<summary><b>会不会在后台自动重连</b></summary>

不会周期性重连。除了你在登录页手动登录，只有启动时可能连接一次（见下），程序不会在背后周期性发认证请求。

启动时的一次连接另有开关：安装版的「设置 → 桌面陪伴 → 启动时自动连接校园网」默认开启（可关闭，下次启动生效），
开启后每次启动用已记住的账号认证一次，本机已在线时跳过，结果显示在校园网页。
便携版不经过这个开关，默认启动时就用已记住的账号认证一次（本机已在线或检测不到校园网认证门户时跳过）；不需要可给 `szudesktop.exe` 加 `--no-auto-login`。
</details>

<details>
<summary><b>账号密码存在哪</b></summary>

Windows 下由 DPAPI 加密，只有这台机器的当前账户能解开，不明文落盘；macOS 走系统钥匙串；
Linux 走 Secret Service。**三端都没有明文兜底**：机器上没有对应的系统安全设施时，
保存会明确报错（`ErrStorageUnavailable`），不会偷偷写一个明文文件；「忘掉账号」还会
顺手清掉老版本可能留下的明文文件。
**认证成功且勾选「记住账号密码」后才会保存**，密码错误时不会覆盖原来存好的凭据。
随时可以「忘掉账号」。
</details>

## 安全与隐私

- **没有使用遥测或统计埋点**：庭院和个人笔记默认留在本机；主动打开学校或飞书官方页面时按相应服务处理数据。飞书导入仅请求你选定且有权限的文档，个人草稿不自动上传
- **笔记与凭据不同**：`notebook-v1.json` 和笔记导出文件是明文；飞书原页登录不接回本地笔记服务，CLI 授权由用户自己的 CLI 管理
- **凭据本地加密**：Windows DPAPI，换机器或换用户都解不开；macOS 钥匙串；Linux Secret Service。没有系统安全设施时拒绝保存并报错，**不落明文文件**
- **业务在学校页面办理**：社区预约、选课和付款由你在官方系统操作；界面上没有代提交入口，服务端也没有任何预约写操作端点（F23 已删），本应用不自动抢位
- **本地服务只绑回环**：桌面服务只监听 `127.0.0.1`，非回环地址会直接拒绝启动；所有 `/api/*` 校验 Host、`Sec-Fetch-Site` 与同源 `Origin`，其它页面的请求一律 403
  除只回报版本的 `/api/health` 和自带校验的 `/api/instance` 外，所有 `/api/*` 还要求本次运行随机生成的凭据：安装版主进程带 `X-SZU-Token` 头；页面首次打开时用一次性的 `?launch=` 参数换成 HttpOnly、SameSite=Strict 的会话 Cookie 并立即跳走，地址栏不留凭据。
- **宿舍区认证是明文的**：学校 Dr.COM 网关默认走 HTTP（`http://172.30.255.42`），这是学校协议的现状、不是本应用的选择；教学区深澜走 HTTPS 且**保留**证书校验
- **不做绕过计费或共享上网的功能**，请遵守学校网络使用规定
- **官方业务只走预设来源**：公告只读取学校公开页面，不提供任意网址代理

## 构建与验证

需要 Go（版本见 `go.mod`）、Python 3 和 Node.js。

```text
python desktop/sync-assets.py      # 同步界面资源（go:embed 需要）
node   desktop/run-checks.mjs      # 全部回归，与 CI 同一入口（见下）
go vet ./... && go test ./...      # 静态检查与单元测试
python desktop/build-windows.py    # 构建 Windows 桌面版单 exe（也是 Electron 包里的 Go sidecar）
node   desktop/electron/build.mjs  # 构建 Windows Electron 安装包（先在 desktop/electron 下 npm ci）
python desktop/smoke_windows.py    # 整机冒烟
python desktop/make_release.py     # 生成发布包（只在真的要发布时跑，会覆盖同名本地产物）
```

`desktop/run-checks.mjs` 自动找到 `desktop/check-*.mjs`、`desktop/electron/check-*.mjs` 与 `desktop/check_*.py`（发布说明、许可、Windows 版本资源等）并逐个运行（第一步是模块语法与链接检查 `desktop/module-links.mjs`），最后汇总失败项、以非零退出码结束；只跑 Node 检查时加 `--only-node`。新增检查按 `check-*.mjs` 或 `check_*.py` 命名放进这些目录即可被发现，不用再改任何清单。

`python desktop/electron/smoke_installer.py` 只在一次性的 GitHub Windows runner 安装、重开、重装和卸载最终安装包；本机开发环境不运行这项安装检查。PR 与标签流水线保留所有构建和安装检查，成功后才发布附件。

发布说明写在根目录的 [CHANGELOG.md](CHANGELOG.md)：升版本号时把 `## 未发布`
那一节改成新版本号，CI 会抽取它作为 GitHub Release 的正文，抽不到就让发布失败。
还没打 tag 的候选版在该节开头单独写一行 `> 候选版：…`，抽取时会被丢掉；
正文其他地方不要写“尚未公开发布”“本地候选版”，否则打 tag 发布时会被拦下。
`python desktop/release_notes.py <版本号>` 可以本地预览；加 `--release` 按打 tag 发布的规则预检（核对版本号与候选版字样）。

界面唯一源文件是 `desktop/index.html` 与 `desktop/assets/garden/`，
构建产物不要手改。默认桌面构建**排除实验 VPN 协议**与未核实的第三方游戏原型美术，
只提供官方 WebVPN 入口；实验源码保留供来源核验与协议研究，不能按已验收功能宣传。
排除方式是构建标签：`internal/vpn` 只被 `//go:build campusvpn` 的文件引用，构建脚本不传
`-tags campusvpn`，所以桌面端和五个平台的命令行发布件里都没有这套协议代码；CI 另外单独编译并测试一次这个标签，保证它不会悄悄坏掉。
`internal/vpn` 的来源与授权仍未核实（STATUS.md F11）：包注释已改成如实说明「来源与授权
尚未核实、不作独立编写的保证」，`F06 / F07 / F08`（假成功、缺超时、跳过证书验证）也都没修。
在来源核实之前，不要把这套实现当成可用功能或干净来源对外宣传。
