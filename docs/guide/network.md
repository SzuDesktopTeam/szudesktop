# 校园网连接与命令行 szunet

这一页介绍怎样在应用里连接校园网、连不上时怎么诊断、接入点编号 ac_id 是怎么回事，以及命令行工具 szunet 的用法。报错原文对照、套餐、代理和官方联系方式，请看 [深圳大学校园网连不上排查指南](../深圳大学校园网连不上排查指南.md)。

## 功能状态

| 功能 | 状态 | 说明 |
| :-- | :-- | :-- |
| 校园网认证 | 🧪 测试中 | 自动识别教学区（深澜）或宿舍区（Dr.COM）后认证，也可以注销或手动指定区域 |
| 接入点编号（ac_id） | 🟡 部分可用 | 按手动指定、本机记录、网关跳转、逐个尝试的顺序取号；识别失败时可以手动填写 |
| 断线诊断 | ✅ 可用 | 列出区域判定、门户是否可达、协议指纹、学校域名是否被代理接管和结论；桌面和命令行都能用 |
| 启动时自动连接 | 🧪 测试中 | 启动时最多用已记住的账号认证一次，可以关闭 |
| 命令行 szunet | 🧪 测试中 | Windows、macOS、Linux 单文件，可登录、注销、查状态、判区、诊断和保存账号 |
| 凭据保管 | ✅ 可用 | 桌面应用用 Windows DPAPI 加密保存校园网账号密码；系统安全设施不可用时拒绝保存，不落明文 |

图例：✅ 可用 · 🟡 部分可用 · 🧪 测试中 · — 不支持。各项的缺口见页末「限制」。

## 在应用里连接

「校园网」页先回答“现在能不能用”：

- 上方「当前连接」显示连接状态，旁边是「刷新状态」和「运行网络诊断」。
- 外网已经可用时，「连接 / 更换账号」表单默认收起，需要时可以展开，重新认证或更换账号。外网能用，不代表填写的账号已经认证。

「当前连接」下面的「校园认证」一栏（首页的网络状态也一样）有几种样子：

| 显示 | 什么意思 |
| :-- | :-- |
| 当前网络出口已在线 | 校园网认证门户确认这台电脑已经在线 |
| 门户未检测到在线会话 | 在校园网里，但还没认证，需要登录 |
| 灰色：外网正常；没有检测到校园网认证页面（不在校园网内时属正常） | 能上外网，但找不到校园网的认证页面。人在校外、用手机热点或家里宽带时就是这样，不用处理。例外：后面还跟着「人在校内的话：代理软件接管了学校域名…」时，说明开着代理软件的 Fake-IP 模式，人在校内就按它改代理设置，见下面的[开着代理软件时](#开着代理软件时) |
| 灰色：没有判定在教学区或宿舍区，没有查询认证状态 | 外网不通，也没认出是哪个区，所以没去查认证状态；先看上面一栏的连接情况 |
| 黄色：校园认证待确认 | 判定你在教学区或宿舍区，却查不到认证状态；这时点「运行网络诊断」 |

第一次连接：

1. 在「连接 / 更换账号」里填校园卡号和统一身份认证密码。
2. 「所在区域」一般保持「自动识别」；也可以手动选「教学区 · 深澜」或「宿舍区 · Dr.COM」。
3. 需要的话勾选「认证成功后记住账号密码」，然后点「登录校园网」。

- 勾选记住时，只有认证成功才会保存；密码错误不会覆盖已经保存的凭据。
- 已经保存凭据后，账号和密码都留空再点登录，会使用已保存的凭据。
- 校园卡号默认隐藏，不会自动填进输入框；要看时点「查看已保存卡号」。
- 「注销连接」让本机下线。
- 想删除保存的账号密码，到「设置 → 存档与隐私」点「删除已保存凭据」。
- 校园网登录和学校业务登录（课表、成绩等）是两件事，要分别办理，见 [校园服务与学校登录](campus.md)。

## 连不上时：运行网络诊断

点「运行网络诊断」，应用会按协议指纹判断你在哪个区域，然后列出：区域判定、互联网是否可用、教学区门户和宿舍区门户是否可达，以及建议。先看结论，再按建议排查；结论后面的「校园网指南 ↗」打开的就是这一页。命令行对应 `szunet diag`。

需要把问题交给别人帮忙看时，先运行一次诊断，再到「设置 → 关于与更新 → 反馈与建议」展开「诊断报告 · 先预览，再复制」，看过再点「复制诊断报告」。报告会带上这次诊断的结论，但接入点编号、IP 和长串数字都已隐去，也不含账号和密码。

### 开着代理软件时

很多同学电脑上开着 Clash 这类代理软件。它的 Fake-IP 模式会把学校的域名解析成 198.18 开头的假地址，访问学校的流量先进代理、再被转出去，于是认证门户或学校系统连不上，或者连上就断。

诊断发现 `net.szu.edu.cn` 被解析到 198.18.0.0/15 时，会在建议里提示：「代理软件接管了学校域名，请把 szu.edu.cn 设为直连（Fake-IP 模式还要把它加进 fake-ip-filter 这类「不分配假 IP」的名单）」。连不上外网时它排在最前；能上外网时排在「当前能正常上外网」那一句之后。能上外网时，「校园认证」一栏的灰色说明后面也会跟上这句，前面写着「人在校内的话」。课表、成绩、学校登录和场地查询连不上时，如果查到出问题的学校域名也被接管，报错里会给出同样的提示。按提示改好代理设置后，再运行一次诊断，这条提示消失才算生效。

这项检查只看 IPv4 的 198.18.0.0/15：代理用 IPv6 假地址，或者开着 TUN 模式但不用 Fake-IP 时，诊断查不出来。连不上学校系统又开着代理的话，可以先临时关掉代理再试。

## 启动时自动连接

程序不会在后台周期性地重新认证，只在启动时最多用已记住的账号自动认证一次，结果显示在「校园网」页：

- 没有记住校园网账号、本机已经在线（不会把已在线的连接挤下线），或检测不到校园网认证门户（例如在校外）时，都会跳过。
- **安装版**：「设置 → 桌面陪伴 → 启动时自动连接校园网」默认开启，每次启动（包括开机自启）认证一次；关闭后下次启动生效。
- **便携版**：没有这个开关，默认每次启动（包括开机自启）连接一次；不需要的话，启动 `szudesktop.exe` 时加 `--no-auto-login` 参数。

## 两套认证系统与判区原理

深大校园网分成两个互不通用的区域，认证方式是两套完全不同的系统：

| 区域 | 系统 | 协议特点 |
| :-- | :-- | :-- |
| 教学区 / 办公区 / 图书馆 | 深澜（SRun） | 2025 年寒假上线；密码经 HMAC-MD5，用户信息经 XXTEA 加密和自定义 Base64，另需 SHA1 校验和 |
| 宿舍区 / 教工区 | Dr.COM（ePortal） | 一次 GET 请求即可完成 |

因此 2024 年以前为 Dr.COM 写的教程和脚本在教学区不再适用，报错信息（如 `ldap auth error`、`Rad:userid error1`、`登陆失败[05]`、`Unknow ac-type`）也不统一。应用会自动判区后认证，连不上时用诊断指出卡在哪一步。

判区不看“门户能不能连上”，而是看**协议指纹**，也就是那套协议特有的握手行为：教学区看 `get_challenge` 能否握手，宿舍区看 ePortal 登录接口是否存在。原因是实测发现，在教学区的机器上访问宿舍门户（172.30.255.42），首页同样返回 200；如果只测连通性，掉线时会误判成宿舍区，并用错误的协议认证。

各条报错的含义和处理办法，见排查指南里的报错对照表。

## 接入点编号 ac_id

校园网每个接入点都有独立的编号（`ac_id`），插在哪个网口就要报哪个号。编号用错（例如固定用 1，而路由器那条线路要求 12）会被服务端直接拒绝。

程序按下面的顺序找编号，从上往下，哪个先成就用哪个：

| 优先级 | 来源 | 说明 |
| :-- | :-- | :-- |
| 1 | 你自己指定的（应用里的「接入点编号」，或命令行 `--ac-id 12`） | 你说了算 |
| 2 | 这台机器在**这个网口**上认证成功用过的 | 成功过一次，直接沿用 |
| 3 | 未认证时被网络拦下，从跳转地址里读出来的 | 自动发现里最可靠的来源，但只在尚未认证时拿得到 |
| 4 | 挨个试常见编号 | 只能说明编号存在，`szunet detect` 会注明是「猜的」；猜出来的编号不会被记下来 |

编号跟墙上的网口走，不跟路由器走：

- 同一台路由器插回原来的口：编号不变。
- 换一个口：编号就变。
- 换一台路由器插原来的口：还是原来的编号。

被服务端拒绝过的编号记录会自动清除，不会一直沿用。

出现「认证失败：ac_id 用错了」时：

- 运行 `szunet detect`，查看当前识别出的区域和接入点编号。
- 自动识别失败时，在「校园网」页展开「高级设置 · 仅在接入点识别失败时修改」，手动填写「接入点编号」；命令行用 `szunet login --ac-id 编号`。

为什么要这样找编号，见开发博客 [校园网认证一直失败，元凶是一个我从没在意过的参数](../blog/ac_id-接入点编号.md)。

## 命令行 szunet

不想开窗口，或者想把认证写进脚本时，可以用命令行工具 `szunet`。在 macOS 和 Linux 上，目前只有这个命令行工具。

### 下载

到 [发布页](https://github.com/SzuDesktopTeam/szudesktop/releases) 选择对应平台的单文件，每个文件都带同名 `.sha256` 校验文件：

| 平台 | 文件 |
| :-- | :-- |
| Windows x64 | `szunet-windows-amd64.exe` |
| macOS（Intel） | `szunet-darwin-amd64` |
| macOS（Apple 芯片） | `szunet-darwin-arm64` |
| Linux（amd64） | `szunet-linux-amd64` |
| Linux（arm64） | `szunet-linux-arm64` |

校验方法见 [下载、安装与更新](install.md)。下面的示例把程序写成 `szunet`，使用时换成你下载的文件名。

**macOS / Linux 首次运行**：从浏览器下载的文件一般没有可执行权限。在终端里进入下载目录，先运行 `chmod +x ./szunet-darwin-arm64`（换成你的文件名），之后用 `./szunet-darwin-arm64 config set` 这样带 `./` 的写法运行。程序没有签名，macOS 可能会拦下首次运行。

### 子命令

| 子命令 | 作用 |
| :-- | :-- |
| `login` | 登录，使用 `config set` 保存的账号；临时换号用环境变量（见下） |
| `logout` | 注销下线；和 `login` 一样认 `--zone`、`--ac-id`、`--ip`，并沿用这张网上次认证成功用的接入点编号 |
| `status` | 查看当前在哪个区、账号在不在线 |
| `detect` | 探测当前网络区域和接入点编号 |
| `diag` | 断线诊断，输出区域判定和协议指纹，给出排查结论 |
| `config` | 管理保存的账号密码：`set` 保存（交互输入，密码不显示）、`show` 查看存放方式和账号、`delete` 删除 |
| `autostart` | 开机自启，仅 Windows：`-on` 打开，`-off` 关闭，不带参数查看当前状态 |
| `vpn` | 校外访问校园网的三条官方通道指引（WebVPN / EasyConnect / 零信任）；只是指引，不含实验 VPN 协议代码。加 `-open 1` 在默认浏览器打开 WebVPN |
| `version` | 查看版本号 |

### 常用参数

| 参数 | 作用 |
| :-- | :-- |
| `-u`、`--user` | 校园卡号（6 位） |
| `-p`、`--password` | 统一身份认证密码（不推荐，见下） |
| `--zone` | 指定区域：`auto`（默认）/ `teaching` / `dorm` |
| `--ac-id` | 手动指定深澜的接入点编号（教学区，一般不用给） |
| `--ip` | 直接指定认证服务器 IP，绕过域名解析 |
| `--json` | 以 JSON 输出，方便脚本调用；`detect --json`、`diag --json` 里的 `srun_dns_fake_ip` 表示学校域名是否被代理的 Fake-IP 接管 |
| `--verbose` | 打印服务端原始返回 |

用 `--help` 查看全部参数。

### 常用示例

```text
szunet config set                   # 先保存账号：交互输入，密码不回显
szunet login                        # 之后直接登录，不用再带密码
szunet detect                       # 看当前识别出的区域和接入点编号
szunet login --zone teaching        # 指定走教学区协议（auto / teaching / dorm）
szunet login --ac-id 12             # 手动指定接入点编号
szunet diag                         # 连不上时先跑它，再按结论排查
```

`config set` 会直接保存输入的账号密码，不会先验证是否正确；保存后用 `szunet login` 试一次。

### 在脚本里使用

- 保存账号时用 `--password-stdin` 从管道传入密码，密码不进命令行参数；这时账号必须用 `-u` 给出：
  `<输出密码的命令> | szunet config set -u 你的卡号 --password-stdin`
- 临时换号可以用环境变量 `SZUNET_USERNAME`、`SZUNET_PASSWORD`。
- `-p` 只为兼容旧脚本保留：密码会留在 shell 历史和进程列表里，使用时会提示风险，不推荐。
- 不要把真实账号密码写进共享脚本或日志。

### 使用前请知道

- szunet 是第三方作品，与深圳大学无关。
- 不要和学校的官方客户端同时使用，两者会互相踢下线。
- 想自己编译，见[参与贡献](../../CONTRIBUTING.md)。

## 命令行保存的账号密码

命令行和桌面应用一样，把账号密码交给系统的安全存储：Windows 用 DPAPI，macOS 用钥匙串，Linux 用 Secret Service（`secret-tool`）。没有对应的系统安全设施时，保存会明确报错，不会写明文文件。各平台怎么加密保存，见[数据、隐私与安全](data-and-privacy.md)。

- `szunet config show` 显示当前的存放方式和已保存的账号，不显示密码；`szunet config delete` 删除。
- macOS：保存失败时会明确报错，也不会退回到把密码写进命令行参数的做法（那样同一台电脑上的其他进程能看到）。如果 `config set` 之后 `login` 读不到已保存的账号，请[反馈](https://github.com/SzuDesktopTeam/szudesktop/issues)；临时可以用环境变量 `SZUNET_USERNAME`、`SZUNET_PASSWORD` 登录。
- Linux：没有 Secret Service 时拒绝保存，同样可以先用环境变量临时登录。

## 限制

- 校园网认证还没在教学区和宿舍区逐项完成现场验收（登录、失败提示、注销、重连）。目前在真实校园网上实测过的是判区、诊断和在线状态查询。启动时自动连接和命令行 szunet 用的是同一套认证，状态相同。
- 接路由器、尚未认证时的接入点编号自动发现，还没有端到端实测；识别失败时请手动填写编号。
- 宿舍区 Dr.COM 认证用的是学校的 HTTP 明文协议，这是学校系统的现状；教学区深澜走 HTTPS，并保留证书校验。
- 还没有接入校园网余额、流量、时长和套餐信息。
- 代理接管学校域名的检查只认 IPv4 的 198.18.0.0/15，IPv6 假地址和不用 Fake-IP 的 TUN 模式查不出来。
- 已经在线时，区域一栏显示「已联网」，还不能显示具体是教学区还是宿舍区。
- macOS 上从下载后的首次运行，到完整的凭据保存再读取（先 `config set`，再 `config show` 或 `login`），都还没有在真机上验证；Linux 没有 Secret Service 时无法保存凭据，也分不清密钥环被锁和没保存过。
- 桌面应用只有 Windows 版；macOS 和 Linux 目前只有命令行 szunet。
- 本项目不做绕过计费或共享上网的功能，请遵守学校网络使用规定。
