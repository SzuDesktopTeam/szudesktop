# 数据、隐私与安全

这一页说明 szuDesktop 把数据存在哪、校园网密码怎么保存、怎么备份和换电脑，以及程序自己会联网做什么。

## 数据存在哪

szuDesktop 的记录默认只存在这台电脑上，放在用户目录（Windows 上一般是 `C:\Users\你的用户名`，Mac 上是 `/Users/你的用户名`，也写作 `~`）下的 `.szunet` 文件夹。Mac 上它是隐藏文件夹，在 Finder 里按 ⌘⇧. 可以显示，或用「前往 → 前往文件夹…」输入 `~/.szunet`。

| 文件 | 内容 | 是否加密 |
| :-- | :-- | :-- |
| `workspace-v1.json` | 庭院存档：伙伴、农田、待办、专注记录、绩点和个人展示 | 否，普通 JSON 文件 |
| `notebook-v1.json` | 课程笔记：课程、笔记、当前草稿和回收站，整本上限 8 MiB | 否，明文 |
| `credentials.json` | 仅 Windows：加密后的校园网账号密码 | 是，Windows DPAPI |
| `session.json` | 仅 Windows：你在备用入口里手动保存的学校登录状态 | 是，Windows DPAPI |
| `session.enc` | 仅 macOS：手动保存的学校登录状态。macOS 版界面不提供手动保存（学校窗口的登录只留在内存里），一般不会有这个文件 | 是，解开它的密钥在钥匙串的 `szunet-session` 条目里 |
| `netpref.json` | 各个网络上次认证成功时用的接入点编号 | 不含账号密码 |
| `*.bak` | 庭院存档和笔记上一份成功保存的版本 | 否，和原文件一样 |
| `*.bak-年-月-日` | 按天备份：最近 3 个用过应用的日子，每天结束时庭院存档和笔记的样子（例如 `workspace-v1.json.bak-2026-09-27`） | 否，和原文件一样 |

- **庭院存档和课程笔记都没有加密**，两者的导出文件也是明文；校园网密码的加密方式不适用于它们。
- 两种 Windows 版本（安装版和便携版）读写的是同一份记录。安装版的桌面伙伴大小、位置等桌面设置由窗口程序另外保存在 `%APPDATA%\szuDesktop`，不在庭院存档里。
- macOS 版的校园网账号密码不在这个文件夹里，而是在系统钥匙串的 `szunet` 条目里（见下文）；桌面伙伴大小、位置等桌面设置保存在 `~/Library/Application Support/szuDesktop`，同样不在庭院存档里。
- 存档是固定的本机文件，程序换了端口重启后也能照常读到。

### 存档出问题时

- **文件损坏**：存档或笔记文件读坏时，会自动用上一份成功保存的版本（`.bak`）恢复，并提示「存档文件损坏，已恢复到上一次成功保存的版本」。`.bak` 也坏了时，改用最近一份能读的按天备份，这时内容可能停在前一个使用日，提示的文字仍是同一句。坏掉的文件改名保留，方便排查。
- **按天备份**：每天第一次保存时，应用先把上一个使用日结束时的存档和笔记另存一份（`文件名.bak-年-月-日`），只留最近 3 个使用日；几天没打开应用不会占名额。误删了笔记里的一大段、或者庭院数值出了问题，`.bak` 已经被新的保存覆盖时，还能从这里找回。
- **手动回到某一天**：先完整退出应用（Windows 安装版用桌面伙伴菜单或托盘的「退出」，Mac 上按 ⌘Q），把当前的 `workspace-v1.json`（或 `notebook-v1.json`）另存一份留底，再把想要的那份 `.bak-年-月-日` 复制一份、改名成 `workspace-v1.json`（或 `notebook-v1.json`），然后重新打开。应用里暂时没有「从按天备份恢复」的按钮。
- **旧版本打开新版本的存档**：以后的版本如果改了存档的结构，再用旧版本打开时会拒绝读取，提示「这份存档来自更新版本的荔枝庭院……请先把应用更新到最新版再打开，原文件不会被改动」（更早的版本提示的是「不支持的存档格式」），不会悄悄丢掉新版本的内容。这时请更新应用，不要点「尝试宽松恢复」：它只保留旧版本认识的内容，确认后会覆盖原存档。
- **庭院存档打不开**：校园网、课程笔记、校园服务和桌面设置不依赖这份存档，照常能用。原存档不会被覆盖，可以选择「导出原始存档」、「尝试宽松恢复」（尽量保留能读懂的伙伴、作物、待办和设置），或用以前导出的备份「从备份恢复」。
- **多个窗口同时打开**：一个窗口保存时，如果另一个窗口已经有更新的记录，会提示「另一个窗口有新记录，已同步」，改用那份较新的记录，不会互相覆盖；这个窗口里刚才没保存上的几步需要重做。笔记遇到冲突时会保留你当前的草稿，并提示先导出，再读取最新版本。

## 校园网密码怎么保存

**什么时候保存**：

- 在应用里，只有校园网认证成功、并且勾选了「认证成功后记住账号密码」时才会保存。密码输错不会覆盖原来存好的账号。
- 命令行 `szunet config set` 会直接保存你输入的账号密码，不先验证是否正确。

**保存在哪里**：

| 平台 | 保存方式 |
| :-- | :-- |
| Windows | DPAPI 加密。只有这台电脑上的当前 Windows 账户能解开，文件被拷走、换电脑或换用户都解不开 |
| macOS | 系统钥匙串里名为 `szunet` 的条目，macOS 版和命令行 `szunet` 共用同一个。钥匙串一次存不下太长的内容，密码超过约 80 个字符时会拒绝保存并说明原因，原来存好的账号保持不变 |
| Linux | Secret Service（需要 `secret-tool`）。没有密钥环的机器可以安装 gnome-keyring 或 libsecret |

三个平台都**没有明文兜底**：电脑上没有对应的系统安全设施时，保存会明确报错并说明原因，不会偷偷写一个明文文件。这时仍然可以每次登录时手动输入账号密码（不保存）。

**查看和删除**：

- 已保存的校园卡号默认不显示，要在「校园网」页主动点「查看已保存卡号」才会出现，也不会出现在首页或导出的存档里。
- 随时可以在「设置 → 存档与隐私 → 账号隐私」点「删除已保存凭据」；命令行用 `szunet config delete`。Mac 上两者删的是同一个钥匙串条目，也可以在「钥匙串访问」里找到 `szunet` 手动删除。系统安全存储不可用时，删除操作也会一并清除早期版本可能留下的未加密凭据文件。

在应用里登录校园网的步骤见[校园网连接与命令行 szunet](network.md)。

## 学校、飞书与琴房的登录

这些登录和校园网密码分开处理：

- **安装版与 macOS 版的学校窗口**：学校原页面在独立窗口里打开，登录状态只保存在内存里，不写入庭院存档，也不落盘。点「清除学校登录」（Mac 上也可以用菜单栏「页面」菜单里的「清除本次学校登录」）或完整退出应用时清除；只关掉主窗口不会清除。
- **便携版备用登录**：登录后的状态只留在内存里；只有你在备用入口里手动保存的登录状态，才会用系统安全存储加密保存，保存不了时拒绝保存。不要把密码或 Cookie 发到聊天或反馈里。
- **学院琴房**：只读查询，登录只保存在内存里，密码不落盘。学校这套系统走 HTTP，请使用该系统的专用密码。
- **飞书**：飞书窗口里的登录只保留到这次应用运行结束；用 `lark-cli` 读取文档的授权由你自己的 CLI 管理。导入只请求你选定、并且有权限的文档，个人草稿不会自动上传，本机副本也不会回写飞书。

具体用法见[校园服务与学校登录](campus.md)和[学习：待办、专注、课程笔记与飞书](study.md)。

## 备份与换电脑

庭院和课程笔记要**分别备份**：庭院备份不包含笔记，笔记备份也不包含庭院。两份导出文件里都没有校园网账号密码。

应用自动留下的 `.bak` 和按天备份都和原文件放在同一个文件夹里，换电脑、重装系统或硬盘出问题时帮不上忙，所以仍要自己定期导出。

**在旧电脑上导出：**

1. 「设置 → 存档与隐私」点「导出庭院与待办」，得到一个 JSON 文件。
2. 同一处点「备份课程笔记」，导出整本笔记；也可以在「学习书屋 → 课程笔记」的课程书架里，打开「导入与备份」点「导出整本备份」。

**在新电脑上恢复：**

1. 安装 szuDesktop，见[下载、安装与更新](install.md)。
2. 「设置 → 存档与隐私 → 从备份恢复」，选择庭院备份文件。这会替换当前的庭院、待办和绩点，不会替换课程笔记；确认前会先校验文件。
3. 在课程书架的「导入与备份」里点「恢复整本备份」，选择笔记备份文件。
4. 到「校园网」页重新登录一次，并勾选「认证成功后记住账号密码」。

`workspace-v1.json` 是普通 JSON 文件，也可以直接复制备份。导出的庭院存档包含你在应用里写下的课程、待办、专注记录和伙伴名字等个人内容，不是匿名文件，请不要公开分享。

## 程序会联网做什么

程序**没有遥测或统计埋点**。庭院和个人笔记默认只在本机；你主动打开学校或飞书官方页面时，数据由对应的服务处理。程序自己发出的网络请求如下：

| 什么时候 | 请求什么 | 带不带账号 |
| :-- | :-- | :-- |
| 窗口停在首页或「校园网」页时，约每 30 秒；手动刷新或认证后也会检查 | 公共联网检测地址 `connect.rom.miui.com`、`www.msftconnecttest.com` 和学校的认证门户，分别判断外网与校园认证状态 | 不带 |
| 需要识别接入点编号时 | 几个公共联网检测地址（如 msftconnecttest、gstatic、captive.apple.com），读取校园网网关的跳转 | 不带 |
| 你登录校园网时，或启动时自动连接的那一次 | 学校的认证网关 | 带校园网账号密码 |
| 打开公告、校历时；校历每天检查一次 | 学校的公开页面 | 不带 |
| 你点「检查更新」时 | 本项目在 GitHub 上的公开发布信息 | 不带学校账号、Cookie 或成绩；和访问任何网站一样，GitHub 会收到你的 IP 等普通请求信息 |
| 你主动使用课表、成绩、场地查询、琴房或飞书时 | 对应的学校系统或飞书 | 按该服务的要求 |

程序不会在后台周期性地发送认证请求，只在启动时最多自动连接一次，规则和关闭方法见[校园网连接与命令行 szunet](network.md)。

新增的微软外网检测来源与认证后刷新属于 2026-10-10 的未发布修复，公开 beta0.9.7 安装包尚不包含，见 [STATUS](../STATUS.md#s74)。

## 本机服务的安全

szuDesktop 在本机运行一个小服务，窗口通过它工作：

- 只监听 `127.0.0.1`，设成其他地址会直接拒绝启动。
- 所有 `/api/*` 请求都校验 Host、`Sec-Fetch-Site` 和同源 `Origin`，其他网页发来的请求一律返回 403。
- 除了只报告版本的 `/api/health` 和自带校验的 `/api/instance`，其余接口还要求本次运行随机生成的凭据：安装版的主进程在请求头里带 `X-SZU-Token`；页面第一次打开时，用一次性的 `?launch=` 参数换成 HttpOnly、SameSite=Strict 的会话 Cookie，随即跳转，地址栏里不留凭据。

效果是：同一台电脑上的其他 Windows 用户即使找到了端口，也读不到你的笔记、存档和成绩。也因为这个凭据每次运行都不同，便携版重启后，旧的浏览器标签页需要从 szuDesktop 重新打开。

## 学校业务在学校页面办理

- 社区预约、选课和付款都由你在学校官方系统里操作。界面上没有代提交的入口，本机服务也没有任何预约写操作接口，程序不会自动抢位。
- 官方业务只走预设的来源：公告只读取学校的公开页面，不提供任意网址代理。
- 本应用不提供绕过计费或共享上网的功能，请遵守学校的网络使用规定。

## 宿舍区认证是明文的

学校宿舍区的 Dr.COM 认证网关默认走 HTTP（`http://172.30.255.42`），账号密码在网络上是明文传输的。这是学校协议的现状，不是本应用的选择。教学区的深澜认证走 HTTPS，并保留证书校验。

- 宿舍区认证出错时，错误信息里不会带出明文密码。
- 不信任所在的网络时：Windows 安装版和 macOS 版可以关掉「设置 → 桌面陪伴 → 启动时自动连接校园网」；便携版不要勾选记住账号，或用 `--no-auto-login` 启动。

## 反馈与安全问题

- 「设置 → 关于与更新 → 反馈与建议 → 复制环境信息」只复制版本、系统类型和界面模式，不包含学号、成绩、密码、Cookie 或存档。
- 同一张卡片里有默认折叠的「诊断报告 · 先预览，再复制」，网络或学校服务出问题时用。报告**包含**：版本与系统、判区、外网是否可用、门户确认在线的区域（教学区或宿舍区）、两类认证门户是否可达、`net.szu.edu.cn` 能否解析、是否被代理的 Fake-IP 接管、系统代理的两个开关（手动代理、自动配置脚本各是开还是关，不含代理地址和端口）、接入点编号的来源类别（不是编号本身）、最近一次网络诊断的结论（接入点编号、IP 和长串数字已隐去），以及这次打开应用后各项学校服务最近一次请求的状态类别、条数和期望字段有没有出现（只有键名和类型）。报告**不包含**：账号、卡号、密码、IP、Cookie、接入点编号、成绩、课表、公告内容和存档。先在卡片里看完全文再复制；复制后由你决定发给谁，应用不会自动上传。
- 「提交反馈 ↗」打开的是[反馈说明](feedback.md)；不管用哪种方式反馈，都请不要附上密码、Cookie 或个人成绩。
- 发现安全问题，请按[安全政策](../../SECURITY.md)私下报告，不要在公开 issue 里写可利用的细节。

## 限制

- 庭院存档（`workspace-v1.json`）、课程笔记（`notebook-v1.json`）和它们的导出文件都没有加密；没有云同步，换电脑要自己分别导出两份备份。
- macOS 上，macOS 版和命令行都把凭据存进钥匙串，但在真机上完整地先保存、再读取（包括更新应用之后再读取）还没有验证。命令行的情况详见[校园网连接与命令行 szunet](network.md)。
- Linux 上密钥环被锁和从没保存过，目前分不出来。
- 本机服务的凭据防的是其他 Windows 用户和其他网页；同一个 Windows 用户下运行的恶意程序本来就能读写你的文件，不在这层防护范围内。
