# 反馈问题与建议

用得不顺、看到显示错误，或者有想要的功能，都欢迎告诉我们。可以发邮件到 **[alakazama@qq.com](mailto:alakazama@qq.com)**，也可以[提交 GitHub Issue](https://github.com/SzuDesktopTeam/szudesktop/issues/new/choose)。邮件不需要 GitHub 账号。

## 在应用里写反馈

打开「设置 → 关于与更新 → 反馈与建议」，展开「写反馈 · 无需账号」：

1. 填写「想做什么」「实际发生了什么」，需要时补充复现步骤和提示原文。
2. 点「预览反馈全文」。应用会附上版本、系统类型和界面模式；诊断报告需要主动勾选才会加入。
3. 检查全文后点「打开邮件草稿」，在默认邮件应用中确认发送。也可以「复制反馈全文」或「保存为文本」，通过自己常用的渠道发送。

草稿只在本次打开期间保留，关闭或刷新前请保存文本。剪贴板不可用时，可选中预览全文手动复制。

### 邮件

「打开邮件草稿」会填好收件人、主题和正文。正文较长时只填收件人和主题，请把全文粘进去，或附上导出的 `.txt` 文件。

没有默认邮件应用时，点「复制邮箱地址」，在常用的邮箱网站或应用中写信。截图请先遮挡个人信息。

### GitHub Issues

GitHub Issues 适合公开跟进讨论，需要一个 GitHub 账号：

1. 打开[新建 issue](https://github.com/SzuDesktopTeam/szudesktop/issues/new/choose)。
2. 用不了、显示不对、闪退，选「问题反馈」；想要新功能，选「功能建议」。
3. 按表单填写，也可以粘贴应用里整理好的反馈。之后的回复会出现在同一个 issue 下面。

## 排查问题时可以附什么

- **环境信息**：点「复制环境信息」，得到版本、系统类型和界面模式。Mac 用户请补充 macOS 版本和芯片类型，可在「苹果菜单 → 关于本机」查看。
- **诊断报告**：网络或学校服务出问题时，展开「诊断报告 · 先预览，再复制」。校园网的问题先运行一次「校园网 → 运行网络诊断」，再复制报告。

诊断报告包含网络是否可达、认证状态、代理开关和学校服务返回的状态与字段结构，不含账号、密码、IP、Cookie、成绩、课表或公告正文。完整字段说明见[数据、隐私与安全](data-and-privacy.md#反馈与安全问题)。

## 发送前检查隐私

- 正文按你填写的内容原样保留。请删去校园卡号、学号、密码、Cookie、令牌、IP 地址和设备信息。
- 请勿附上个人成绩、课表，截图也要遮挡这些信息。
- 反馈内容由你预览并发送，应用不会自动上传。未勾选诊断报告时不会加入学校服务记录，也不会读取笔记、公告正文、存档或截图作为附件。

可被利用的漏洞或账号泄露问题，请按[安全政策](../../SECURITY.md)私下报告，不要在公开 issue 中披露。
