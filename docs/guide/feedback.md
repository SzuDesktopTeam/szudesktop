# 反馈问题与建议

用得不顺、看到显示错误，或者有想要的功能，都欢迎告诉我们。这一页写的是**现在**能用的反馈方式。应用里的「提交反馈 ↗」和页面底部的「问题与建议 ↗」打开的就是这一页，以后换了渠道只改这里，已经装好的应用不用更新。

## 现在怎么反馈

**不用先注册账号，也能在应用里把问题整理好。** 打开「设置 → 关于与更新 → 反馈与建议」，展开「整理一份反馈 · 无需登录」：

1. 写下「想做什么」「实际发生了什么」，复现步骤可以补充点击顺序和提示原文。
2. 点「预览反馈全文」。应用只附上版本、系统类型和界面模式；诊断报告需要你主动勾选才会加入。
3. 确认内容后「复制反馈全文」或「保存为文本」。草稿只在本次打开期间保留，关闭或刷新前请先导出。剪贴板不可用时，也可以选中预览全文手动复制。

**整理、复制和导出都不会自动提交。** 正文按你填写的内容原样保留，请先删去密码、Cookie、学号和个人成绩，再交给维护者。

### 直接发邮件（不需要 GitHub 账号）

公开反馈邮箱：**[alakazama@qq.com](mailto:alakazama@qq.com)**。

预览反馈全文后，可以点「发邮件反馈」，在系统默认邮件应用中打开收件人、主题和正文已填好的草稿。检查后由你发送，应用不会自动发邮件。正文较长时，邮件草稿只填收件人和主题；请把复制的全文粘进去，或附上导出的 `.txt` 文件。

没有设置默认邮件应用时，点「复制邮箱地址」，在自己常用的邮箱网站或应用里写信即可。普通问题可以附上已经遮挡个人信息的截图。

### GitHub Issues（适合跟进公开讨论）

也可以通过 GitHub Issues 反馈，需要一个 GitHub 账号（可以免费注册）：

1. 打开[新建 issue](https://github.com/SzuDesktopTeam/szudesktop/issues/new/choose)。
2. 用不了、显示不对、闪退，选「问题反馈」；想要新功能、希望某处改一改，选「功能建议」。
3. 按表单填写，或把应用里整理好的文本分别粘贴到对应字段，再提交。之后的回复会出现在同一个 issue 下面。

参加试用的同学，按招募你的同学告诉你的方式交回就行，不用另开 issue。

## 写什么最有用

- 当时想做什么、点了哪里、卡在哪一步，以及界面上提示的原文。
- 用的是哪种形态：Windows 安装版、Windows 便携版、macOS 版（Apple 芯片或 Intel），还是命令行 szunet。Mac 上再写上 macOS 版本（「苹果菜单 → 关于本机」里能看到）。
- **环境信息**：在应用里打开「设置 → 关于与更新 → 反馈与建议」，点「复制环境信息」，粘贴到反馈里。它只有版本、系统类型和界面模式三行。
- **诊断报告**（网络或学校服务出问题时）：在同一张卡片里展开「诊断报告 · 先预览，再复制」，看过全文再点「复制诊断报告」。校园网的问题，先在「校园网」页点一次「运行网络诊断」再复制。报告只列判区、认证门户能不能连上、系统代理开没开、最近一次网络诊断的结论，以及各项学校服务返回了哪些字段；不含账号、卡号、密码、IP、Cookie、成绩、课表或公告内容。具体包含什么，见[数据、隐私与安全](data-and-privacy.md)。

## 请不要附上

- 校园卡号、统一身份认证密码、Cookie、令牌。
- 成绩、课表、学号，以及带有这些内容的截图。截图前请先遮挡个人信息。
- IP 地址和在线设备信息。

应用不会自动上传任何东西：反馈正文、环境信息和诊断报告都是你复制或导出以后，自己决定发给谁。没有勾选诊断报告时，反馈文本不会自动加入学校服务记录；也不会读取你的笔记、公告正文、存档或截图作为附件。

## 安全问题

可被利用的漏洞，或者可能泄露账号密码、Cookie 的问题，请不要发在公开的 issue 里，按[安全政策](../../SECURITY.md)用私有漏洞报告提交。
