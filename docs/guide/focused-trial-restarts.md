# 浏览器试用候选：快速重启验收

> **浏览器方案，不作为 1.0 门槛。** 这是 2026-10-01 准备的浏览器试用候选，需要现有 Node.js。1.0 前的首轮试用改用原生安装包，按[试用自查清单](trial-checklist.md)和[首轮试用观察表](trial-observation.md)进行（维护者 2026-10-05 的决定，见[开发状态](../STATUS.md#s73)）。本页保留，供以后单独比较浏览器方案时参考。

这是未发布的浏览器候选，需要现有 Node.js 22+ 和 Windows x64，**不是原生安装包或正式版**。本轮实际执行环境为 Node.js 26.7.0。Go 引擎仍为发布版 beta0.9.5，未重新编译；未安装软件、升级依赖、操作系统权限或学校账号。

## 修复的触发场景

旧候选 `944c402` 在确认退出后仍延迟 100ms 才关闭。立刻重开可能复用正在退出的旧 Go 服务，旧服务随后结束，新页面读取存档失败。原数据仍完整，但入口不可用。此前隔离实测记录了该故障；当前候选已补充试用目录级实例协调。

- 只有同一目录、同一候选、身份匹配、健康且未退出的实例才复用。
- 退出确认前先标记退出中；等待自己的 Go 进程和 HTTP 服务结束后释放实例锁。
- 同一试用目录保留固定本地 origin 与会话凭据，重开继续使用同一入口。记录不随包分发。
- 等待启动或退出最多 12 秒；端口冲突、版本冲突或记录损坏明确失败，保留原数据，不换端口，不关闭占用服务。
- 只回收本次启动器自己创建的引擎，不终止无关进程。

## 本轮已验

1. 同时启动两次：同一入口与会话，仅一个实例持有目录。
2. 退出确认后立即重开五次：每次为健康新实例；origin、会话、照料记录、课堂笔记、课程和选中位置一致。
3. 原端口被自建无关服务占用：启动器退出码 1 且明确报错，无替代入口；占用服务继续正常响应。关闭该测试服务后，原入口与数据恢复。
4. 同一真实 Chromium 浏览器中三次保存正文、立即重启、刷新再继续写：Cookie、正文、已关闭的欢迎引导及摸头记录保留，无页面异常。
5. 协调模块回归：身份不匹配、服务不健康、退出中、不同候选、有限等待、已退出 PID 的锁恢复及损坏入口记录保留。
6. 104 个模块语法与链接检查、54 组 JS 检查通过。首次受限运行有一组 sidecar 检查无法结束自己创建的进程；仅该组在获准隔离范围外重跑，34 项通过。

证据放在候选包 `evidence/restarts/`。截图来自实际页面，笔记均为合成数据。32 秒正常使用演示保持原视频，不将重启压力测试拼成正常用户演示。

## 复现和试用

保留解压后的同一目录。运行 `START.cmd`，在浏览器打开控制台链接。写一段合成课堂笔记，等“已保存到本机”，返回首页摸头，再从设置退出并立刻重开 `START.cmd`；检查原链接、正文和伙伴状态。双击两次应得到同一链接。

构建同类候选无需安装依赖或新编译器：在源码根目录执行 `node desktop/package-focused-trial.mjs <beta0.9.5引擎绝对路径> <尚不存在的输出目录>`。引擎 SHA-256 必须为 `f7ef69a8ed04a516e7620c45ee315d61d898faeab3520860b243746d0fded5fb`。模块与 JS 检查执行 `node desktop/run-checks.mjs --only-node`；进程回收测试需要允许结束测试自己创建的进程。

不要在运行中搬动或复制试用数据目录；不要删除入口记录来绕过报错。强制终止控制台、断电、杀毒隔离及机器睡眠恢复尚未验收。遇到无法确认的旧服务，启动器保留数据并拒绝复用，需要本人关闭自己的旧试用实例后重试。
