# ADR 0004：不做服务端，个人数据只留在本机

- 状态：已接受（2026-09 起实施，2026-11-06 追溯整理）
- 相关：`desktop/internal/ui/workspace.go`、`desktop/internal/ui/notebook.go`、`internal/credential/`、`docs/guide/data-and-privacy.md`

## 背景

课程笔记、待办、专注记录、庭院存档，加上学校会话能读到的成绩和课表，都属于个人信息。产品是给本人用的工具，不是多人协作平台。

## 备选方案

| 方案 | 好处 | 为什么不选 |
|---|---|---|
| 自建后端 + 账号体系 | 能同步、能做统计、能多人协作 | 要长期运维、要处理个人信息合规、要防泄露；对单人工具类应用，收益远小于责任 |
| 第三方云 BaaS | 上手快 | 把「数据不出本机」变成对第三方的信任承诺，还引入供应链和停服风险 |
| **纯本机** | 无账号、无遥测、离线可用 | 见下节代价 |

## 决定

- 数据落本机 JSON（命令行与引擎用 `~/.szunet`，Electron 侧用 `userData`），学校会话进系统安全存储；笔记与庭院存档分开备份。
- 没有账号体系、没有服务端、没有遥测、没有自动更新；升级靠用户去发布页重新下载。
- 网络请求只有两类：学校公开信息与本人授权的只读业务，以及网络诊断；不上传任何本机内容。
- 飞书文档是**只读导入**：在官方原页协作，本机生成带来源的副本，副本不回写、不做双向同步。
- 跨设备靠用户手动导出／导入备份，不做隐式同步。

## 代价与边界

- 不能跨设备同步，不能多人共同编辑（协作交给原页面），换机器要自己搬存档。
- **没有使用统计，产品侧就缺真实用户证据**：发布下载次数、issue 和 PR 是可查的，但「哪些功能被打开过」看不到。后续若要做统计，也只能做本地、可选、可导出、默认不上传的形式，不能推翻这条决定。
- 「无服务端」也让自动更新、推送提醒、崩溃汇总这类能力都不能做。

## 怎么验证

`docs/guide/data-and-privacy.md` 对用户公开说明数据位置；`docs/STATUS.md` 的当前摘要明确写「无服务端部署、无遥测」；`check-*.mjs` 里有针对网络请求与外链资源的静态检查；发版前敏感词自查不因为「没有服务端」而省略。
