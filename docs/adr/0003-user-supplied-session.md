# ADR 0003：学校会话由用户自己提供，不做登录自动化

- 状态：已接受（2026-09 起实施，2026-11-06 追溯整理）
- 相关：`internal/credential/session.go`、`desktop/internal/ui/browser_session.go`、`desktop/internal/ui/ehall.go`、`desktop/internal/ui/session.go`、`desktop/internal/ui/scores.go`

## 背景

学校几个业务应用共用一个统一身份认证的会话域，公告、成绩、课表、场馆查询都需要本人登录态。要在应用里读这些，就得先解决「登录态从哪来」。

## 备选方案

| 方案 | 为什么不选 |
|---|---|
| 复刻统一身份认证登录（加密盐、验证码、二次验证） | 要接触用户密码，还要跟学校登录页的加密脚本和风控变化赛跑；一旦失效，用户会以为是账号出了问题 |
| 内嵌浏览器让用户自己登录，再自动接管会话 | 拿到的仍然是同一种 Cookie，却多出一整套 WebView 生命周期、代理分流和窗口权限问题；作为后续备选，不作为第一步 |
| **让用户从自己已登录的浏览器复制会话，应用只负责保管和使用** | 选中；不需要碰密码，也不重放任何二次验证 |

## 决定

- `internal/credential/session.go` 定义 `SessionStore`，用系统安全存储保存会话（Windows DPAPI、macOS Keychain、Linux Secret Service），**与校园网账号凭据分开存、分开取**；平台不支持时明确报「存储不可用」，不退化成明文文件。
- `browser_session.go` 只把用户交来的 Cookie 放进内存 Cookie Jar 供只读请求使用，不落盘；`/api/session/check` 只回报会话长度，不回显内容。
- 所有请求走 Go 侧客户端，页面不直接接触学校域名；学校域名请求必须**绕过系统代理**（`Transport{Proxy: nil}`），否则本机开着代理时会被 Fake-IP 接管，拿到假响应。
- 只读优先：成绩、课表、场馆时段、馆藏位置。拿到行却解析出 0 门课时必须报错，**绝不显示「没有成绩」**——`checkSuspiciouslyEmpty` 就是这条底线，因为「解析错了」和「真的没数据」在界面上长得一样。
- 会话失效时明确提示重新导入，不猜、不自动重试登录。

## 代价与边界

- 用户要手动导入，过期要重导；做不了无人值守的后台同步，也无法在锁屏状态下刷新。
- 应用能力受限于「用户本人有权看到什么」，不会比官方页面更多。
- 认证态 WebView 是明确的后续选项，但它产出的是同一种 Cookie，所以后端这层设计不需要推翻。

## 怎么验证

`session` 相关测试覆盖「只回报长度」「明文不落盘」「0 门课报错」；真实账号只读验证要有公告正文、成绩、馆藏位置的实际响应记录，且不能把模拟响应当作通过（`docs/STATUS.md` 的验收章节按这个口径写）。
