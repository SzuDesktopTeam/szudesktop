# ADR 0002：本机服务用随机端口，并在每次启动时生成凭据

- 状态：已接受（2026-09 起实施，2026-11-06 追溯整理）
- 相关：`desktop/internal/ui/api_guard.go`、`desktop/internal/ui/server.go`、`desktop/internal/ui/instance_lock_*.go`、`desktop/electron/listen-url.mjs`

## 背景

引擎在回环地址上开 HTTP 服务，页面能读笔记、待办、庭院存档，还能借用户导入的学校会话查成绩和课表。同机任何进程、以及用户浏览器里任何网页，只要猜到端口就能请求这个服务。固定端口加「只监听 127.0.0.1」挡不住本地恶意页面，也不挡其他本地进程。

## 备选方案

| 方案 | 为什么不选 |
|---|---|
| 固定端口、不鉴权 | 任何本地进程都能读笔记、借会话查成绩 |
| 启动时生成 token 但落盘复用 | 凭据长期有效，泄露窗口跟存档一样长 |
| 只检查 Origin / Referer | 这两个头由客户端提供，本地进程可以随意伪造 |
| **随机端口 + 每次启动现生成凭据 + 逐接口校验** | 选中；代价是启动握手和日志脱敏 |

## 决定

- `Addr` 默认 `127.0.0.1:0`，端口由系统分配，不写死。
- `api_guard.go` 用 `crypto/rand` 生成 32 字节随机串（64 位十六进制）。Go 1.24 起 `rand.Read` 不返回错误：系统随机源不可用时直接终止进程，不会退化成弱凭据。
- 除健康检查外，每个 `/api` 都包在 `protectAPI` 里：请求带 `X-SZU-Token` 头或 `szu_session` Cookie 与本次运行的凭据一致才放行；比较用恒定时间比较，响应时间不泄露凭据前缀。
- 页面入口靠一次性的 `?launch=` 参数把凭据换成 Cookie，参数本身要校验回环 Host 和 token。
- `listen-url.mjs` 的 `redactToken` 在日志和启动失败信息里把凭据打码。
- 单实例锁 `acquireInstance` 让第二个进程复用已有实例的地址和凭据并广播「已复用」，而不是再开一个服务。

## 代价与边界

- Electron 主进程必须解析引擎 stdout 才能拿到地址和凭据，握手变成启动关键路径，任何一行输出格式变化都会让启动卡住。
- 用户手动开浏览器要带 launch 参数；崩溃转储、诊断日志都要脱敏，多了一处长期要盯的地方。
- 这只防「同机其他程序」，不防「同机同用户」；本机数据本来就归用户自己，威胁模型到此为止。

## 怎么验证

`api_token_test.go` 逐条扫描包内所有生产 Go 文件的路由注册，断言每个 `/api` 都经过 `protectAPI`（见 ADR 0008）；`api_guard_test.go` 覆盖无凭据、错误凭据、令牌格式与恒定时间比较；真实二进制冒烟要验证「无凭据被拒」「公开白名单不变」「未知路径返回统一 JSON 404」。
